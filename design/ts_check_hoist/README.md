# `ts_check_hoist/`

Locks where a component's `// @ts-check` / `// @ts-nocheck` goes in the
overlay. svelte2tsx copies the ones its script opens with to the top of
the generated file (`extractTsCheckComment`), so they decide whether
TypeScript checks the component: `@ts-check` turns checking on for a
JavaScript component in a `checkJs: false` project, `@ts-nocheck` turns
it off for a TypeScript one. Our overlay opens with its own
`// generated by svelte-check-native` line; the directive goes right
below it, still among the file's leading comments, which is where
TypeScript reads pragmas from.

```sh
tsgo -p design/ts_check_hoist/tsconfig.json
```

Expected, with `allowJs: true, checkJs: false`:

- `check.svelte.svn.js(4,14)`: TS2339 (`@ts-check` turns checking on);
- `plain.svelte.svn.js`: nothing (no directive, `checkJs` is off);
- `nocheck.svelte.svn.ts`: nothing (`@ts-nocheck` turns checking off);
- `checked.svelte.svn.ts(3,5)`: TS2322 (no directive);
- `last-wins.svelte.svn.js(5,14)`: TS2339 (both directives: the last
  one wins, as TypeScript's pragma handling has it).
